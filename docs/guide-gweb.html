Qu’est-ce que GWEB ?

GWEB est la version documentée et exportable de la stack HealthDesire : un WordPress “funnel-first” prêt à être cloné, déployé et scalé — sans les données clients ni les logs tracker.

Pour les ops

Déployer une nouvelle instance avec LPs, boutique, forms et cloak déjà câblés.

Pour les ads

URLs stables ?page_id=, pixel multi-compte nourri, merci = custom conversion.

Pour les agents IA

Contrat clair dans AGENTS.md : quoi toucher, quoi ne jamais casser.

Pixel Meta propre

1 loader · N init · 1 PageView — primary ads en tête.

White assets

Bibliothèque /white/{produit}/ pour créas LP légères.

Parcours utilisateur (ads → lead)

Click Meta→ LP routée→ PageView pixel→ Popup form→ Lead Espo→ Merci / convert
  1. L’annonce pointe vers https://domaine/?page_id=SOURCE&utm_….
  2. Le router mappe SOURCE → page WP (ex. 2461 → Fire Bowl V4).
  3. Le visiteur autorisé (geo) voit la LP + popup ; les bots peuvent être filtrés.
  4. À la soumission : lead local + Espo + meta fbp/fbc/fbclid.
  5. Redirection merci (custom conversion Meta sur l’URL).

Pixel & signal ads

Déployer le prototype

Procédure détaillée : docs/DEPLOY.md. En quatre mouvements :

  1. Installer WordPress frais + importer sql/01 → 02 → 04.
  2. Rsync wordpress/wp-content + dossier white/.
  3. search-replace domaine + flush rewrites + admin neuf.
  4. Secrets VPS, smoke test lead + pixel + Espo.

Checklist go-live

  • LP ads (page_id source) charge la bonne créa
  • Popup visible, submit → row lead + Espo OK
  • Meta lead contient fbp / fbclid
  • Merci charge le pixel (PageView)
  • Cloak : TN/MA/DZ OK ; bot preview géré
  • Aucun dump leads dans le repo
